# Research References and Applicability

External sources were checked against official project documentation or author-maintained repositories where accessible. Project evidence is kept separate from published evidence. A paper or library result is not an expected AUC gain on this dataset.

| Topic and source | What it establishes | EXP85 assessment / validation required |
|---|---|---|
| **TabM**, Gorishniy et al., ICLR 2025, [paper and official Yandex repository](https://github.com/yandex-research/tabm), [arXiv 2410.24210](https://arxiv.org/abs/2410.24210) | Parameter-efficient ensemble of MLP-like predictors with shared weights; author repo reports broad tabular benchmark evaluation and a PyTorch package. | TabM is not found as a historical trained EXP85 component in the inspected lineage reports. It is a hypothesis for complementary signal, not a presumed upgrade. Requires a valid CUDA PyTorch install; current base Python lacks PyTorch and the 4050 has 6 GiB. First run should be a bounded memory/runtime feasibility test, then identical folds and seeds, early stopping inside fold only. Compute: medium/high; GPU capable in principle, not presently ready. |
| **XGBoost GPU support**, [official documentation](https://xgboost.readthedocs.io/en/stable/gpu/) | Current documented GPU usage uses `tree_method="hist"` and `device="cuda"`; documents ELLPACK and memory guidance including `QuantileDMatrix`. | XGB10 and zoo XGBoost already exist; another model is low priority until component feature/fold parity is resolved. Current RTX is available; confirm loaded booster config and runtime telemetry; fail instead of CPU fallback. Compute: medium. |
| **CatBoost GPU training**, [official documentation](https://catboost.ai/docs/en/features/training-on-gpu) | `task_type="GPU"` and device selection enable GPU; CatBoost explicitly states GPU training is nondeterministic because floating-point summation order is nondeterministic. | Historical and Phase 2 models use CatBoost. Save actual logs/device utilization and accept tolerance-based reproducibility; do not attribute every parity delta to GPU without controlled device-only comparison. Compute: medium; 6-GiB card constrains batch/data/iterations. |
| **LightGBM GPU**, [official GPU tutorial](https://lightgbm.readthedocs.io/en/stable/GPU-Tutorial.html), [parameters](https://lightgbm.readthedocs.io/en/stable/Parameters.html#device_type) | GPU support is a separately built backend; enabling the parameter does not install or add that backend. | The local LightGBM build is reported to lack its GPU tree learner. Current supported path is CPU; do not claim GPU or silently rebuild/install. Compute: CPU-heavy, current threads and RAM should be recorded. |
| **Leakage-safe target encoding**, [scikit-learn TargetEncoder documentation/source](https://scikit-learn.org/stable/modules/preprocessing.html#target-encoder) | Target encoding needs cross-fitting to prevent each training row's own target from leaking into its encoded feature; standard transformer pipelines keep fitting inside training subsets. | Phase 2 already implements nested OOF target encodings and has explicit self-exclusion/apply-label-independence tests. A repeat is not justified; new encoders must preserve the same outer/inner boundaries and compare to Phase 2 on matched folds. |
| **Categorical boosting**, Prokhorenkova et al., NeurIPS 2018, [CatBoost paper](https://arxiv.org/abs/1706.09516) | Ordered boosting and ordered categorical statistics address prediction shift/target leakage effects in categorical boosting. | CatBoost is already a Phase 2 ensemble member and a historical family. Categorical interactions may be tested only if OOF complementarity is shown and fold isolation is preserved. |
| **Feature selection under CV**, scikit-learn [common pitfalls and leakage guidance](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage) | Any transformation/selection informed by labels must be fit using the training partition only; nesting is needed for an unbiased outer estimate. | Historical 550-feature screening is a critical parity feature but a global full-label screen is not a valid outer-CV estimate. Reproduce historical selection for fidelity separately; use nested selection for generalization claims. Compute: high for 669 × multi-fold models, mostly CPU under current LightGBM. |
| **Stacking**, Wolpert, “Stacked Generalization,” *Neural Networks* (1992), [DOI](https://doi.org/10.1016/S0893-6080(05)80023-1) | A learned meta-model can combine diverse generalizers, but its training features must be out-of-fold predictions to avoid leakage. | Historical suite uses fixed weights/rank-probit transforms; Phase 2 selected a fixed 50/50 blend. Optimize only in inner folds and test on outer folds; do not learn weights against the historical test champion. Compute: low after base OOF is available. |
| **Covariate shift**, Shimodaira, “Improving predictive inference under covariate shift,” *J. Statistical Planning and Inference* (2000), [DOI](https://doi.org/10.1016/S0378-3758(00)00115-4) | Reweighting can be useful under covariate shift under its assumptions; those assumptions must be checked, not presumed. | The historical apex and Phase 2 frequency features use unlabeled test covariates (transductive). Evaluate train/test shift from covariates only, and compare inductive/fold-local versus explicitly transductive variants. No causal/score gain is assumed. Compute: low/medium; risk: validation protocol mismatch. |
| **Distributionally robust validation** | Standard CV can be optimistic if observations/groups/time are not exchangeable; report stratified-fold variance and meaningful cohort slices. | The official split is not an external future cohort. Keep fixed stratified folds for continuity, plus predeclared group/temporal stress tests only when the data semantics support them. Never use historical predictions as labels. |
| **Graph/borrower similarity methods** | Similarity diffusion can exploit repeated entities but creates strong leakage risks if edges connect held-out labeled rows or encode identity/outcomes. | Historical Anchor74 describes borrower matching and test-to-test smoothing; raw test has covariates only. Audit collisions, edge precision, and fold-local graph construction before any model test. Graph methods are low priority until the historical entity-key logic is source-verified. Compute: medium; CPU feasible. |

## Evidence classes

- **Published evidence:** statements in the papers and official library docs linked above.
- **Project evidence:** source code, run logs, frozen manifests, and numerical results in this workspace/history.
- **Hypothesis:** an untested proposed transfer to this competition. No benefit estimate is asserted for hypotheses.
