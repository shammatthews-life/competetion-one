# EXP11 — Historical Component Recovery

EXP11 independently rebuilds the historical EXP85 suite's XGB10 component from
the raw competition CSVs. Lineage documentation describes it as a 239-feature
Hist-XGBoost model with a 10-fold historical OOF AUC of 0.774331 and a 25.96%
weight in the historical 8-engine suite. The available full-data generator
actually emits 173 features, so EXP11 pins that source and does not invent the
66 undocumented features. The OOF cache is provenance evidence, not a fresh
result.

The fresh run preserves the fixed XGB10 feature formulas and tree parameters,
but corrects two validation issues in the historical runner:

- Categorical vocabularies and frequencies are fit on the current training
  partition only.
- Early stopping uses an inner split of the outer training rows. The outer
  validation labels are used only for scoring.

The Phase 2 OOF baseline, labels, ordered IDs, and fold membership are loaded
from EXP10's independently verified shared-baseline contract. Its fold
membership is exactly `StratifiedKFold(n_splits=5, shuffle=True,
random_state=20261102)`. The XGB model seed is 20261103; this is a fresh model
seed, while the folds intentionally remain those of the matched baseline.
Changing fold membership would invalidate the comparison.

Run from the repository root:

```powershell
python champion\EXP85_CHAMPION_IMPROVEMENT\experiments\exp11_historical_component_recovery\source\run_exp11.py
python champion\EXP85_CHAMPION_IMPROVEMENT\experiments\exp11_historical_component_recovery\source\verify_exp11.py
python -m unittest discover -s champion\EXP85_CHAMPION_IMPROVEMENT\experiments\exp11_historical_component_recovery\tests -v
```

The runner requires the RTX 4050 CUDA path and exits rather than falling back
to CPU. All reported AUC values are OOF metrics, not public leaderboard scores.
No historical champion files are modified, and no submission is generated by
this experiment.
